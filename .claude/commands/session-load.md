# 会话恢复 / 新建 Skill

## 角色设定
你是我的学术助手。每次新对话开始时，你不确定我是想继续之前的工作，还是开始一个全新的话题。你的任务是帮我快速决策和切换。

## 触发条件
- 我说 `/session-load` 或 "加载会话"、"恢复对话"、"上次聊到哪了"
- 或这是新对话的**第一轮**，你可以主动提醒："需要我加载之前的会话进度吗？你也可以直接开始新话题。"

## 核心流程

### 第一步：读取索引
读取 `.claude/session-logs/INDEX.md`，获取所有历史会话列表。

如果 INDEX.md 不存在或为空 → 直接告诉我"没有找到历史会话记录，这可能是你的第一个对话"，然后正常开始。

### 第二步：展示会话列表
按时间倒序展示最近的会话，格式如下：

```
📋 最近的会话记录：

[1] 2026-07-17  论文阅读：抗生素抗性基因    [已完成]
[2] 2026-07-16  MS-MINT 数据导入报错调试     [进行中]
[3] 2026-07-15  论文阅读：微生物群落分析      [已完成]

你想怎么做？
A. 延续 [1] / [2] / [3]（输入数字）
B. 开启全新话题（输入 N 或直接说新问题）
```

**最多展示最近 5 条**，更早的折叠为"…还有 X 条更早的会话，需要查看吗？"

### 第三步-A：延续已有会话
如果我选择了某个会话：

1. 读取对应的 `session-logs/YYYY-MM-DD-xxx.md` 文件
2. 向我呈现恢复的上下文（精简版，不超过 20 行）：

```
🔄 已恢复会话：[2026-07-16] MS-MINT 数据导入报错调试

📌 当时进度：数据已导入但 run() 时报 MemoryError，
   我们排查到可能是多线程 Pool 导致的，还没解决。

📝 关键上下文：
   - 你用的是 Windows 10，MS-MINT 装在 D:\koier\MS-MINT_Program\
   - 错误发生在 Mint._run_parallel() 的 pool.map_async() 调用
   - 任务管理器显示内存没满，怀疑是 32-bit Python 地址空间限制
   - 上一个建议是用 mint.run(nthreads=1) 串行测试，还没试

⏳ 未完成：
   - 用 nthreads=1 测试是否还报内存错误
   - 检查 Python 是 32-bit 还是 64-bit

⚠️ 文件时效性检查：
   - 会话记录时间：2026-07-16（距今 1 天）
   - 相关文件最近修改：{如果有变化会标注}
```

3. 确认上下文后，自然衔接继续聊

### 第三步-B：开启新话题
如果我选择开启新话题：

1. 简短确认："好的，开始全新话题。之前会话的进度都保存在 `.claude/session-logs/` 里，随时可以用 `/session-load` 恢复。"
2. 不再加载任何历史上下文，直接进入新话题

### 智能判断（可选优化）
如果我在新对话第一轮就直接开始问问题（没有调用 `/session-load`）：
- 先正常回答问题
- 回答完后轻量提醒："对了，上次你有会话 [X] 还没完成，需要恢复进度吗？不需要的话忽略就好。"

## 防幻觉机制（来源：handover-skills）
> 当恢复的摘要信息可能与实际文件状态不一致时，遵循以下信任优先级：

1. **实际文件/代码** > 会话摘要
2. **测试输出/报错信息** > 文字描述
3. **最近的 git 状态** > 手写记录

如果发现摘要和实际情况冲突（比如摘要说"已经修复了"但文件里 bug 还在），主动告诉我并纠正。

## 禁止事项
- 不要在没有读取 INDEX.md 的情况下编造会话列表
- 延续会话时不要跳过"上下文恢复确认"这一步
- 不要一次展示超过 5 条历史会话（信息过载）
- 如果历史会话超过 7 天，要加"⚠️ 此会话已超过一周，部分上下文可能已过时"的提示

## 完成标志
- [ ] 我选择了延续或新话题
- [ ] 如果延续，上下文已恢复并确认
- [ ] 进入正常的对话流程
